# Пабометр · Москва — мониторинг цен официальных меню

**Новые адаптеры документов и динамических меню:** см. [MENU_ADAPTERS_RU.md](MENU_ADAPTERS_RU.md). Доступны PDF с текстом, сканы и изображения через необязательный Tesseract OCR, динамический HTML через Playwright (необязательная установка), CSS-селекторы. OCR-результаты отправляются на ручную проверку и не публикуются как подтверждённые цены. Загрузчики не означают автоматическое подключение пабов без проверенного официального меню.


Готовый локальный проект для **Python 3.10**. Streamlit показывает цены горячих блюд
и пива, сравнение, историю, изменения меню и состояние источников. SQLite хранит
наблюдения; GPU, PostgreSQL и платный API для сбора не нужны.

**Актуальный реестр — 23 паба с ценами (37 источников)**. Восемьдесят три паба без извлекаемых цен исключены из активного мониторинга после проверки 18 ноября 2026 года. Исходные 106 записей сохранены в `archive/pubs_before_price_cleanup_2026-11-18.json`; исключённые — в `archive/excluded_pubs.json`. Подробности каждого источника: `price_audit_results.json` и отчёт `COVERAGE_AUDIT.csv` (46 строк, по двум категориям каждого активного паба). Это не утверждение о закрытии или отсутствии меню у исключённых заведений: доступных для текущего парсера проверенных цен не получено.
**Обновление установленного проекта: сначала прочтите UPDATE_RU.md.**
География ограничена **ЦАО, САО и СВАО**; другие округа конфигурация отклоняет.

## 1. Быстрый запуск на Windows 10

1. Распакуйте ZIP целиком, например в `C:\Projects\pub_price_monitor`.
2. Откройте `setup_windows.bat`. Он создаст `.venv` именно на Python 3.10 и установит зависимости.
3. Откройте `start_dashboard.bat`.
4. В браузере перейдите на **http://localhost:8501**.
5. На вкладке **«Источники»** нажмите **«Проверить цены сейчас»**.

Архив обновления не содержит папку data, чтобы не перезаписать вашу историю.
При первой установке выполните сбор. Через 48 часов цены требуют повторной проверки.

Если Python Launcher `py` не найден, используйте терминал PyCharm:

```powershell
python --version
# Должно быть Python 3.10.x
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m streamlit run app.py
```

В PyCharm: **Open → папка проекта → Settings → Project → Python Interpreter →
Add Interpreter → Existing → `.venv\Scripts\python.exe`**.
Команды запускайте из папки с `app.py`, `sources.json` и `requirements.txt`.
Активация PowerShell-окружения не обязательна, поэтому ошибка ExecutionPolicy
не мешает запуску через полный путь к Python.

Реестр собран по каталогам MoscowPubs и ЕдаНяма и сайтам пабов 16–17.11.2026.
Каталоги используются только для поиска, ни одна цена из них не попадает в базу.
Для каждой строки реестра сохранена ссылка поиска. Филиалы — отдельные записи.
Неподтверждённая запись не доказывает, что заведение работает. Полнота охвата не гарантируется.

Супы, гарниры, десерты, холодные и горячие закуски не относятся к основным горячим
блюдам в этой версии. Сезонные спецпредложения вне перечисленных разделов не
подмешиваются. Сидры исключаются, включая известные названия, попавшие на сайтах
в пивные разделы. Безалкогольное пиво хранится с отдельным признаком.

У части пабов сайт загружает позиции из публичного каталога Tilda. Агент сначала
читает официальную страницу, получает из неё идентификаторы разделов и только
потом запрашивает **тот же каталог**, который использует сайт. Это не сторонний
агрегатор цен. Все ответы сохраняются со ссылкой и SHA-256.

## 3. Что показывает дэшборд

- **Обзор:** охват, свежесть, обычная аналитическая сводка; опционально ИИ-комментарий.
- **Цены и сравнение:** позиция, порция, цена, тип подачи, источник, предыдущая цена,
  абсолютное/процентное изменение, примечания и экспорт CSV для Excel.
- **История:** график конкретной позиции с неизменной порцией и типом подачи,
  включая исчезнувшие из последнего меню позиции; экспорт истории.
- **Изменения меню:** повышение/снижение цены, новые позиции, отсутствие в новом меню.
- **Все пабы:** реестр, адреса, ссылки, подтверждение и состояние подключения.
- **Источники:** адреса, ручное обновление выбранных пабов, даты и ошибки по каждому меню.

Для каждого нового замера сохраняется полная распознанная выборка, даже если
цены не поменялись. История появляется **с начала наблюдений**, а не за прошлые месяцы.
Первый замер не объявляется ростом или снижением. Повторные запуски в один день
не являются отдельными днями истории — на графике это время проверки.

### Сопоставимость

- 280 мл и 568 мл — разные позиции. Цена за 0,5 л считается как `цена × 500 / объём_мл`.
- В сравнении пива используется одна порция на название/паб/тип/признак безалкогольности,
  ближайшая к 500 мл. При равном расстоянии выбирается большая.
- Стейки с ценой **за 100 г** отделены от цен за порцию.
- Названия блюд разных пабов автоматически не признаются одинаковыми продуктами.
  График распределения показывает ассортимент, а не стоимость идентичной корзины.
- Если объём не указан, цена остаётся в таблице, но не входит в расчёт за 0,5 л.
- Если сайт написал «0,33 мл», агент не исправляет это догадкой: сохраняет текст,
  цену и предупреждение; пересчёт отключён.
- Переименование или смена порции создаёт новую позицию. Автоматическое нечёткое
  объединение названий намеренно не используется, чтобы не смешивать разные блюда.

## 4. Актуальность и ошибки

«Проверено» означает, что агент недавно успешно прочитал **опубликованное меню**.
Это не гарантия, что владелец сегодня обновлял сайт или что блюдо есть в наличии.
Дата проверки и дата обновления меню — разные вещи; вторую сайт часто не сообщает.
Отсутствие строки в новом меню не считается подтверждённым отсутствием в пабе.

- `ok` — все выбранные разделы обработаны; отдельные предупреждения об объёме возможны.
- `partial` — некоторые строки не удалось разобрать; подробности в диагностике.
- `review` — слишком мало позиций или их число упало более чем на 35% против прошлого полного снимка.
- `error` — HTTP-ошибка, таймаут, robots.txt, изменившаяся разметка и т. п.

При partial/review/error последний полный снимок не заменяется. Он становится
помеченным «Требует проверки» и исключается из сравнительных графиков свежих цен.
Если полного снимка никогда не было, строки partial доступны как неполные данные.
Review не входит в ценовую таблицу. Проверяйте сохранённое меню, если сокращение
ассортимента действительно произошло: адаптер/порог нужно настроить осознанно.

Публичные страницы запрашиваются с паузой, таймаутом, ограничением размера ответа,
проверкой robots.txt и двумя повторами временных ошибок. CAPTCHA и блокировки не
обходятся. Одновременный сбор из окна и планировщика защищён файловой блокировкой.

## 5. Автоматическая ежедневная проверка в Windows

Дэшборд не обязан быть открыт. Создайте задачу в **Планировщике заданий Windows**:

1. «Создать задачу», имя `MoscowPubPriceMonitor`.
2. Триггер: ежедневно, например **10:00 по московскому времени**. Убедитесь, что
   часовой пояс Windows соответствует нужному времени.
3. Действие «Запуск программы»:
   - Программа: `C:\Projects\pub_price_monitor\.venv\Scripts\python.exe`
   - Аргументы: `-m monitor.cli collect`
   - Рабочая папка: `C:\Projects\pub_price_monitor`
4. В параметрах включите «Выполнить задачу как можно скорее после пропуска запуска».
5. При уже работающей задаче выберите «Не запускать новый экземпляр».
6. Для проверки нажмите «Выполнить» и посмотрите вкладку «Источники» и `data\monitor.log`.

Подставьте свой путь к проекту. Компьютер должен быть включён и иметь доступ в
интернет. При работе от батареи снимите соответствующее ограничение, если нужно.

Код завершения: `0` — все выбранные меню обработаны полностью; `2` — есть
partial/review/error; `1` — ошибка запуска/конфигурации или уже выполняется сбор.
Расписание автоматически не регистрируется и задача в ChatGPT не создаётся.

Команды вручную:

```powershell
.\.venv\Scripts\python.exe -m monitor.cli collect
.\.venv\Scripts\python.exe -m monitor.cli collect --only dubliner
.\.venv\Scripts\python.exe -m monitor.cli collect --only delirium_beer
.\.venv\Scripts\python.exe -m monitor.cli status
.\.venv\Scripts\python.exe -m monitor.cli export --output data\prices.csv
```

Linux/VPS (тот же Python 3.10):

```bash
python3.10 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
.venv/bin/python -m monitor.cli collect
.venv/bin/python -m streamlit run app.py
```

Для круглосуточного сбора можно перенести проект на VPS и запускать CLI через
cron/systemd. Интерфейс по умолчанию слушает только `127.0.0.1` и не имеет
авторизации: для публикации в интернет понадобится отдельный защищённый доступ.

## 6. Где здесь ИИ

Базовый агент сам получает меню, проверяет структуру и качество, извлекает цены,
сохраняет снимки, считает изменения и строит отчёт. Эти действия детерминированы.

**Дополнительный LLM-модуль** делает короткую аналитическую записку по выбранным
свежим наблюдениям. Он не подменяет сбор и не записывает цены в базу.

В `.env`:

```dotenv
AI_API_KEY=ваш_ключ
AI_BASE_URL=https://api.openai.com/v1
AI_MODEL=gpt-4.1-mini
AI_MAX_COMPLETION_TOKENS=1800
```

Можно использовать совместимый с Chat Completions провайдер, изменив адрес и
точный идентификатор доступной у него модели. Провайдер должен поддерживать
`max_completion_tokens`; для иных API адаптируйте `monitor/ai.py`.
Ключ хранится локально в `.env`, не вводится в браузере и не входит в архив.
После изменения `.env` перезапустите дэшборд.

Отправляются до 180 строк выбранных **свежих** данных, в первую очередь изменения;
объём выборки передаётся явно. Идентичный запрос кэшируется в `data/ai_cache`.
Нет обязательных ежедневных расходов на LLM: запрос выполняется по кнопке.
Модель по умолчанию — пример доступного API-интерфейса, а не заявление о самой
дешёвой модели. Наличие модели, региональный доступ и тариф проверьте у провайдера.

API-контракт проверен по официальной документации:
https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create
https://developers.openai.com/api/docs/models/gpt-4.1-mini

Живой платный запрос без пользовательского ключа не выполнялся. Формат запросов,
ошибки, кэширование и неполные ответы проверены тестами с подменённым API.
ИИ-текст может содержать ошибки интерпретации: сверяйте его с таблицей.

## 8. Расширение списка

Универсального надёжного парсера для любого сайта нет. Чтобы добавить паб:
проверьте официальный домен, конкретный адрес в ЦАО/САО/СВАО, тип меню (зал, доставка,
общесетевое), затем добавьте запись в `sources.json` и подходящий адаптер.

Адаптер Tilda подходит только сайтам с таким же публичным каталогом и структурой
заголовков. Обычно он извлекает ID разделов из свежей страницы. Для «Лиги Пап», где подписи
вкладок не совпадают с содержимым, используются проверенные ID разделов; их наличие
повторно проверяется в HTML при каждом запуске.
Если API отдаёт меньше строк, чем `total`, сбор этого источника останавливается:
нужно добавить пагинацию, а не принимать частичный каталог за полный.

Поддержаны текстовые PDF Post Pub и несколько схем HTML. Другие PDF, фотографии
и динамические меню требуют отдельного проверенного адаптера/OCR. Меню
доставки и общесетевые цены не переносите автоматически на конкретный зал.
При первом подключении сверяйте таблицу со страницей и добавляйте тестовые примеры.
